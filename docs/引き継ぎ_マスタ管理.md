## 1. 何を作ったか

### `/admin/users`（マスタ管理・管理者専用）

タブ6つの1画面です。以前は「ユーザー管理」だけの画面でした。

| タブ | できること |
|---|---|
| 👤 メンバー | 表示名の仮設定・ロール変更・無効化・削除・招待 |
| 🚩 優先度 | 高/中/低 の表示名と色を変更 |
| 📊 状態 | 未着手/進行中/完了 の表示名と色を変更 |
| 🏷 種別 | 6区分の表示名を変更 |
| 📋 定型タスク | 雛形の閲覧（**編集は未実装**） |
| ✉️ 共有先 | 宛先一覧・送信スケジュール・手動送信・送信履歴 |

レイアウトは**ヘッダーと左のタブ一覧が固定**で、右のパネルだけがスクロールします
（`md` 未満では通常のページスクロールに戻ります）。

### `/tasks`（進捗管理）

- 左に**仮のサイドバー**（上記①）
- サイドバーの「定型タスク」→ **最前面にモーダル**で雛形一覧 → 名前を入れて生成
- ヘッダーの「メール共有」ボタンは**削除**（共有先タブに統合したため）

### 削除した画面

- `src/app/tasks/mail/page.tsx`（メール共有の設定）→ **共有先タブに統合**
- `/tasks/templates` は `/tasks` へのリダイレクトのみ残しています

## 2. 崩してほしくない設計原則

**どれも理由があって選んでいます。** 変えるときは理由ごと更新してください。

### 原則1：コード値は固定、ラベルと色だけをデータにする

`tasks.priority` に入るのは `high`/`mid`/`low` のままです。**マスタで変えられるのは見せ方だけ。**

- `tasks` テーブルには**一切手を入れていません**（マイグレーション不要）
- `priority` / `status` / `task_type` には **DBのCHECK制約**があるため、値を増やすにはスキーマ変更が要ります
- 特に `"done"` は**アプリ内の約25か所**で直接判定されています（進捗率・アーカイブ・植林・オフィス・親子の自動完了・完了時の実績時間必須）。
  「どれを完了として扱うか」をマスタで変えられるようにすると**進捗率が静かに壊れます**

### 原則2：テーブルが無くても動く（フォールバック必須）

`loadPriorityMeta()` などは、**テーブルが無い／読めないときはコード内の既定値を返します**。

マスタが読めないだけで一覧が真っ白になるのは避けたいからです。
新しいマスタを足すときも同じ形にしてください。

### 原則3：色は「キー」で保存する（CSSを保存しない）

Tailwind は**ソースコードに書かれたクラスだけ**をCSSに出力します。
DBに `bg-red-100` と保存しても、**そのCSSが生成されず色が付きません。**

なので DB には `red` のようなキーだけを入れ、実際のクラスへの変換は
`src/lib/priorities.ts` の `PRIORITY_COLORS` / `statuses.ts` の `STATUS_COLORS` が持ちます。
副産物として、読めない配色（薄い黄色に白文字など）を作れなくなります。

### 原則4：権限はサーバで強制する（UIで隠すだけにしない）

管理系の書き込みはすべて `/api/admin/*` を通し、`requireAdmin()` で検証しています。
マスタのテーブルには **read ポリシーしか付けていません**。書けるのはサービスロール（＝サーバ）だけです。

具体的に守っているルール：

| 操作 | 禁止している相手 |
|---|---|
| 表示名の変更 | **本人が自分で設定した名前**（管理者でも触れない。仮のままなら直せる） |
| ロール変更・無効化・削除 | **自分自身**、**最後の管理者** |

いずれも**ボタンを隠すだけでなく API が 400/403 を返します。**

### 原則5：使い道のない列は作らない

「将来使うかも」で列を足していません。実際に見送ったもの：

- 優先度の `weight`（成果ポイント廃止で誰も使っていない）
- 優先度・状態の `sort_order`（3つ固定なら並べ替える意味がない）
- 種別の `color`（種別はプルダウンにしか出ないので色を置く場所がない）
- メンバーの `color` / `sort_order`

必要になった時点で足せば、そのとき用途がはっきりします。

### 原則6：破壊的な操作は影響を明示してから

アカウント削除は確認ダイアログで「担当タスク件数」「AI内田さんの会話履歴も消える」
「元に戻せない」を出します。また**削除前に担当タスクへ表示名を文字列で書き写す**ので、
過去タスクが「担当者なし」になりません（`tasks.assignee` が元々そのためのフォールバック列）。
